# 📖 Introduction

Process control with signals is an important Linux administration topic.

A Linux process may need to be:

- Interrupted
- Suspended
- Resumed
- Terminated
- Forced to stop
- Notified about an event

Linux performs these actions using **signals**.

---

# 1. What Is a Signal?

A signal is:

> **A software interrupt delivered to a running process.**

A signal informs a process that a particular event has occurred or requests that the process perform a specific action.

For example, a signal may ask a process to:

- Stop temporarily.
- Continue running.
- Terminate gracefully.
- Terminate immediately.
- Reload its configuration.
- Respond to a terminal event.

---

# 2. Why Are Signals Important?

Suppose a process is running on the system.

As a user or administrator, you may want to:

- Interrupt the process.
- Change its state from Running to Stopped.
- Resume a stopped process.
- Terminate it.
- Forcefully kill it if it does not respond.

Signals provide a standard method for controlling processes without directly modifying the program.

---

# 3. Events That Generate Signals

Signals may be generated by:

- Keyboard shortcuts
- Errors
- Hardware events
- Terminal events
- The Linux Kernel
- Another process
- A command such as `kill`
- A shell job-control command

Examples:

| Event | Signal |
|------|--------|
| Pressing `Ctrl + C` | `SIGINT` |
| Pressing `Ctrl + Z` | `SIGTSTP` |
| Terminal closes | `SIGHUP` |
| `kill PID` | `SIGTERM` by default |
| `kill -9 PID` | `SIGKILL` |

---

# 4. List All Available Signals

Use:

```bash
kill -l
```

This command displays the names and numbers of all available signals.

Example:

```text
1) SIGHUP
2) SIGINT
9) SIGKILL
15) SIGTERM
18) SIGCONT
19) SIGSTOP
20) SIGTSTP
```

Signal numbers may vary on some architectures, so `kill -l` should be used to verify them on the current system.

---

# 5. Create a Long-Running Foreground Process

Use the `sleep` command with a large number.

```bash
sleep 1000
```

This process remains active for 1,000 seconds.

Because no ampersand (`&`) was used:

- The process runs in the foreground.
- The terminal is occupied.
- The shell prompt is unavailable.
- The process receives terminal keyboard input.

---

# Foreground Process Flow

```text
User Runs sleep 1000
        │
        ▼
Shell Starts a Process
        │
        ▼
Process Runs in Foreground
        │
        ▼
Terminal Remains Occupied
```

---

# 6. Stop a Foreground Process with `Ctrl + Z`

While the command is running, press:

```text
Ctrl + Z
```

Expected Output:

```text
[1]+  Stopped    sleep 1000
```

The process is suspended.

It has not been terminated.

---

# What Happens Behind the Scenes?

When you press:

```text
Ctrl + Z
```

the terminal normally sends:

```text
SIGTSTP
```

to the foreground process group.

On standard x86_64 Linux systems, its common signal number is:

```text
20
```

---

# 7. Verify the Stopped Process

Run:

```bash
jobs
```

Expected Output:

```text
[1]+  Stopped    sleep 1000
```

For more detail:

```bash
jobs -l
```

Example:

```text
[1]+ 2500 Stopped    sleep 1000
```

Here:

- `[1]` is the Job ID.
- `2500` is the Process ID.
- `Stopped` is the job state.

---

# 8. What Is `SIGTSTP`?

`SIGTSTP` means:

> **Signal Terminal Stop**

It requests that a process stop or suspend its execution.

Common signal number:

```text
20
```

It is commonly generated by:

```text
Ctrl + Z
```

---

# Important Property of `SIGTSTP`

A process may:

- Catch `SIGTSTP`
- Handle `SIGTSTP`
- Ignore `SIGTSTP`
- Block `SIGTSTP`

Therefore, an application may choose how to respond.

---

# 9. Start a Background Process

Run:

```bash
sleep 2000 &
```

Example Output:

```text
[2] 2502
```

The ampersand (`&`) causes the process to run in the background.

The shell prompt returns immediately.

---

# Verify the Background Job

Run:

```bash
jobs -l
```

Example:

```text
[1]- 2500 Stopped    sleep 1000
[2]+ 2502 Running    sleep 2000 &
```

---

# 10. Stop the Background Process with `SIGTSTP`

You can send `SIGTSTP` using either:

- Job ID
- Process ID

---

# Using the Job ID

```bash
kill -SIGTSTP %2
```

The `%` symbol tells the shell that `2` is a Job ID.

---

# Using the PID

Suppose the PID is:

```text
2502
```

Run:

```bash
kill -SIGTSTP 2502
```

You can also use the signal number:

```bash
kill -20 2502
```

---

# Verify the State Change

Run:

```bash
jobs
```

Expected Output:

```text
[1]-  Stopped    sleep 1000
[2]+  Stopped    sleep 2000
```

The second process changed from:

```text
Running
```

to:

```text
Stopped
```

---

# 11. Find a Process ID with `ps`

To find the PID of a command named `sleep`, use:

```bash
ps -C sleep
```

Example Output:

```text
PID TTY          TIME CMD
2500 pts/0    00:00:00 sleep
2502 pts/0    00:00:00 sleep
```

A more detailed command is:

```bash
ps -C sleep -o pid,ppid,stat,cmd
```

Example:

```text
PID   PPID STAT CMD
2500  2400 T    sleep 1000
2502  2400 T    sleep 2000
```

The `T` in the `STAT` column means:

```text
Stopped
```

---

# 12. Job ID vs Process ID

| Identifier | Example | Managed By |
|------------|---------|------------|
| Job ID | `%2` | Current shell |
| PID | `2502` | Linux Kernel |

Job IDs only work in the shell where the job was started.

PIDs identify processes system-wide.

---

# 13. Send Signals by Name or Number

Both forms are valid.

Using the signal name:

```bash
kill -SIGTSTP 2502
```

Using the signal number:

```bash
kill -20 2502
```

Using a Job ID:

```bash
kill -SIGTSTP %2
```

---

# 14. What Is `SIGSTOP`?

`SIGSTOP` also stops or suspends a process.

Common signal number:

```text
19
```

Command:

```bash
kill -SIGSTOP PID
```

or:

```bash
kill -19 PID
```

---

# Important Property of `SIGSTOP`

Unlike `SIGTSTP`, `SIGSTOP` cannot be:

- Caught
- Handled
- Blocked
- Ignored

The Linux Kernel forces the process into the Stopped state.

---

# 15. `SIGTSTP` vs `SIGSTOP`

| Feature | `SIGTSTP` | `SIGSTOP` |
|---------|-----------|-----------|
| Meaning | Terminal stop request | Forced stop |
| Common Number | `20` | `19` |
| Sent by `Ctrl + Z` | Yes | No |
| Can be caught | Yes | No |
| Can be ignored | Yes | No |
| Can be blocked | Yes | No |
| Enforced by Kernel | Not absolutely | Yes |

---

# 16. When Should `SIGSTOP` Be Used?

Use `SIGSTOP` when:

- A process ignores `SIGTSTP`.
- A process must be suspended immediately.
- You need a Kernel-enforced stop.
- Normal job-control suspension does not work.

Example:

```bash
kill -SIGSTOP 2502
```

---

# 17. Verify a Process State with `ps`

Use:

```bash
ps -o pid,ppid,stat,cmd -p 2502
```

Example:

```text
PID   PPID STAT CMD
2502  2400 T    sleep 2000
```

The process state:

```text
T
```

means the process is stopped.

---

# 18. Process State Flow

```text
Running Process
      │
      ├── Ctrl + Z
      │      │
      │      ▼
      │   SIGTSTP
      │      │
      │      ▼
      │   Stopped
      │
      └── SIGSTOP
             │
             ▼
          Stopped
```

---

# 19. Stop Does Not Mean Terminate

A stopped process:

- Still exists.
- Keeps its PID.
- Remains in memory.
- Does not continue normal execution.
- Can later be resumed.
- Is visible in `jobs`, `ps`, and `top`.

A terminated process:

- Finishes or is killed.
- Releases most resources.
- Eventually disappears from process listings.

# 🔧 Troubleshooting Scenarios

### Scenario 1 – `Ctrl + Z` Does Not Stop the Process

The process may be handling or ignoring `SIGTSTP`.

Use:

```bash
kill -SIGSTOP PID
```

---

### Scenario 2 – `kill -SIGTSTP %2` Reports No Such Job

The job may:

- Belong to another shell.
- Already be complete.
- Have a different Job ID.

Check:

```bash
jobs -l
```

Or use the PID:

```bash
ps -C process_name
```

---

### Scenario 3 – Multiple `sleep` Processes Exist

Use:

```bash
ps -C sleep -o pid,ppid,stat,cmd
```

Confirm the correct PID before sending a signal.

---

### Scenario 4 – Process State Is Not Changing

Verify that:

- You have permission to signal the process.
- The PID is correct.
- The process still exists.
- You used the correct signal.

Check:

```bash
ps -p PID
```

---

# ⚠️ Important Safety Notes

- Always verify the PID before sending a signal.
- Do not stop critical system processes without understanding their purpose.
- A stopped service process may make the service unavailable.
- Job IDs are local to the current shell.
- Root can normally signal processes owned by other users.
- A normal user can generally signal only processes that they own.

# 📖 Key Takeaways

- A signal is a software interrupt delivered to a process.
- Signals are used to control and notify running processes.
- `kill -l` lists the available signal names and numbers.
- `Ctrl + Z` normally sends `SIGTSTP`.
- `SIGTSTP` changes a process from Running to Stopped.
- `SIGSTOP` also stops a process but cannot be caught or ignored.
- Signals can be sent using either Job IDs or PIDs.
- The `T` process state means Stopped.
- Stopping a process is different from terminating it.
- Always verify the correct target before sending a signal.

---

# 💡 Remember

> **Think of a signal as an instruction sent to a worker.**
>
> - `SIGTSTP` means: **“Please pause your work.”**
> - `SIGSTOP` means: **“Stop immediately, whether you want to or not.”**
>
> **Golden Flow:**
>
> ```text
> Running Process
>       │
>       ├── Ctrl + Z / SIGTSTP
>       │              │
>       │              ▼
>       │           Stopped
>       │
>       └── SIGSTOP
>              │
>              ▼
>           Stopped
> ```
>
> **Use `SIGTSTP` for normal suspension and `SIGSTOP` when the process must be stopped forcefully.**
