# 📖 Introduction

In this lesson, we will begin learning about:

```text
Nginx
```

Nginx is one of the most widely used technologies for serving and managing web traffic.

Although many people think of Nginx primarily as a:

```text
Web Server
```

it is important to understand that its design goes beyond simply serving web pages.

At its core, Nginx is also a:

```text
Reverse Proxy Server
```

This architectural design is one of the reasons Nginx performs so well under heavy workloads.

---

# History of Nginx

Nginx was created in:

```text
2004
```

by Russian developer:

```text
Igor Sysoev
```

Nginx was developed because of concerns about the way existing web servers handled large numbers of simultaneous connections.

The goal was to build a system capable of handling:

```text
10,000 Concurrent Connections
```

while maintaining:

* High performance
* High concurrency
* Low memory usage

---

# Why Was Nginx Created?

The main design goal was to efficiently handle many clients at the same time.

Conceptually:

```text
Client 1 ─────┐
Client 2 ─────┤
Client 3 ─────┤
Client 4 ─────┤
Client 5 ─────┤
              ▼
            Nginx
              │
              ▼
     Thousands of Connections
```

Instead of becoming inefficient as the number of connected clients increased, Nginx was designed to handle large numbers of concurrent connections effectively.

---

# What Is Concurrency?

Concurrency means:

> **Handling multiple operations or connections during the same period of time.**

For a web server, this may mean handling requests from many users at once.

Example:

```text
User 1 ───────┐
User 2 ───────┤
User 3 ───────┤
User 4 ───────┤
User 5 ───────┤
              ▼
          Web Server
```

A highly concurrent web server is designed to manage many such clients efficiently.

---

# Nginx Is More Than a Web Server

Although Nginx is commonly described as a web server, that is not the complete picture.

At its core, Nginx is designed to work extremely well as a:

```text
Reverse Proxy
```

This is an important concept.

---

# What Is a Reverse Proxy?

A reverse proxy sits between clients and backend servers.

Instead of clients connecting directly to the backend application, they connect to Nginx.

Nginx then forwards the request to the appropriate backend server.

Conceptually:

```text
Client
   │
   ▼
Nginx
Reverse Proxy
   │
   ▼
Backend Server
```

The response follows the reverse path:

```text
Backend Server
      │
      ▼
Nginx
      │
      ▼
Client
```

---

# Basic Reverse Proxy Architecture

```text
                 Client
                    │
                    ▼
              ┌───────────┐
              │   Nginx   │
              │ Reverse   │
              │   Proxy   │
              └─────┬─────┘
                    │
          ┌─────────┼─────────┐
          │         │         │
          ▼         ▼         ▼
      App Server  App Server  App Server
          1           2           3
```

---

# Why Use a Reverse Proxy?

A reverse proxy can provide several benefits.

Examples include:

* Hide backend servers from clients.
* Route traffic to different applications.
* Distribute traffic.
* Cache responses.
* Terminate HTTPS connections.
* Improve performance.
* Centralize access control.

# Why Reverse Proxy Design Matters

The reverse proxy design allows Nginx to efficiently manage connections between:

```text
Many Clients
```

and:

```text
One or More Backend Servers
```

Example:

```text
Client 1 ────┐
Client 2 ────┤
Client 3 ────┤
Client 4 ────┤
             ▼
           Nginx
             │
      ┌──────┼──────┐
      ▼      ▼      ▼
    App 1  App 2  App 3
```

This architecture is common in modern web environments.

# Nginx and Caching

Nginx can also cache content.

Instead of asking the backend server for the same information every time, Nginx may be able to store a copy temporarily.

Conceptually:

```text
Client Request
      │
      ▼
    Nginx
      │
      ├── Cached?
      │      │
      │   ┌──┴──┐
      │   │     │
      │  Yes    No
      │   │     │
      ▼   │     ▼
Return    │  Backend Server
Cached    │       │
Content   │       ▼
          └── Store Response
```

Caching can reduce load on backend systems.
