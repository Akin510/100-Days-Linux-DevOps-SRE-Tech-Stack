# 1. What is System Logging?

Whenever a Linux system is running, the **Operating System**, **Kernel**, and various **applications** continuously record important events.

These recorded events are called **System Logs**.

System logs help administrators:

- Monitor system activity
- Audit system events
- Troubleshoot problems
- Identify hardware or software failures
- Detect security incidents

---

# 2. Why Are Logs Important?

Imagine users begin reporting that:

- The system is running slowly.
- Logging into the application takes a long time.
- An application keeps crashing.
- Services are failing to start.
- CPU, Memory, or Disk usage is unusually high.

The very first thing a Linux System Administrator should do is:

> **Check the system logs.**

Logs provide valuable information about what happened on the system and often reveal the root cause of the problem.

---

# 3. What Information Do Logs Contain?

Linux logs record many different types of events, including:

- User logins and logouts
- Failed login attempts
- Service startup and shutdown
- Kernel messages
- Hardware errors
- Disk errors
- CPU and Memory issues
- Application events
- Scheduled cron jobs
- Boot process messages

# 5. Which Services Handle Logging?

On Red Hat Enterprise Linux (RHEL) and other Red Hat-based distributions, logging is typically handled by **two services**.

| Service | Responsibility |
|----------|----------------|
| `systemd-journald` | Collects log messages |
| `rsyslog` | Processes and stores log messages |

### Interview Question

**Question:**

Which services are responsible for logging on a Red Hat Linux system?

**Answer:**

- `systemd-journald`
- `rsyslog`

These two services work together to collect, manage, and permanently store log messages.

---

# 6. What is systemd-journald?

`systemd-journald` is the primary logging service provided by the **systemd** framework.

Its responsibility is to collect event messages from multiple sources across the operating system.

---

## Sources of Log Messages

The `systemd-journald` service gathers log messages from:

- The Linux Kernel
- Early boot process
- System daemons
- Standard Output (`stdout`)
- Standard Error (`stderr`)
- Syslog events

This makes `systemd-journald` the central collector for almost all system events.

---

# 7. Where Are Journal Logs Stored?

By default, journal logs are stored in a temporary filesystem located under:

```text
/run
```

This storage is:

- Temporary
- Memory-based
- Not persistent across system reboots

Because `/run` resides in memory, all journal logs stored there are lost when the system reboots unless persistent journal storage has been configured.

---

# 8. What is rsyslog?

After `systemd-journald` collects the log messages, another service called **rsyslog** processes them.

Its responsibilities include:

- Reading log messages from the system journal
- Processing the messages
- Writing them to the appropriate log files
- Forwarding logs to remote logging servers if configured

---

# 9. Responsibilities of rsyslog

The `rsyslog` service performs several important tasks.

It:

- Reads log messages generated by `systemd-journald`
- Sorts log messages according to their priority
- Organizes logs based on the application that generated them
- Stores logs in permanent log files
- Supports remote log forwarding

Without `rsyslog`, collected log messages would not be written to their permanent log files.

---

# 10. Permanent Log Storage

Unlike journal storage under `/run`, `rsyslog` stores logs permanently in:

```text
/var/log
```

Everything stored inside `/var/log` remains available even after the system is rebooted.

---

# 11. Common Log Files

| Log File | Purpose |
|----------|---------|
| `/var/log/messages` | General system messages |
| `/var/log/secure` | Authentication and security events |
| `/var/log/maillog` | Mail server logs |
| `/var/log/cron` | Cron scheduler logs |
| `/var/log/boot.log` | Boot process messages |

Each log file receives messages according to the application and the priority level defined in the rsyslog configuration.

# 13. What is Logrotate?

Linux systems continuously generate log files.

If these log files continue growing without any maintenance:

- They consume large amounts of disk space.
- System performance may degrade.
- Finding important information becomes difficult.
- Disk partitions can become full.

To solve this problem, Linux uses a utility called **Logrotate**.

---

# 14. What is Logrotate?

**Logrotate** is a Linux utility that automatically manages log files.

It can:

- Rotate old log files
- Create new empty log files
- Compress archived logs
- Remove very old logs
- Prevent log files from growing indefinitely

Logrotate usually runs automatically through scheduled system jobs.

---

# 15. Why is Log Rotation Important?

Log rotation provides several benefits:

- Saves disk space
- Keeps log files organized
- Improves system performance
- Archives historical logs
- Makes backups easier
- Simplifies troubleshooting

Without log rotation, log files can eventually consume all available storage.

---

# 16. Typical Log Rotation Process

```text
Current Log File
        │
        ▼
Log File Reaches Size or Age Limit
        │
        ▼
Rename Existing Log
        │
        ▼
Create New Empty Log
        │
        ▼
Compress Old Log
        │
        ▼
Delete Older Archived Logs Based on Retention Policy
```
