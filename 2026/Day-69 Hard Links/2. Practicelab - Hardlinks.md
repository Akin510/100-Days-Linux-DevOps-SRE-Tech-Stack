# 📖 Introduction

In the previous lesson, we learned the theory behind **Hard Links** and **Soft Links**.

In this lab, we will create a Hard Link and observe its behavior.

Remember:

A Hard Link is simply another filename that points to the **same inode** as the original file.

Both filenames access exactly the same data stored on disk.

# 🔬 Lab 2 – Create a Hard Link

The command used to create a Hard Link is:

```bash
ln
```

General Syntax:

```bash
ln <original_file> <hard_link_name>
```

Example:

```bash
ln file1 file1-H
```

Where:

- `file1` → Original file
- `file1-H` → Hard Link

You may use any name for the Hard Link.

---

# Verify the Hard Link

Display the files:

```bash
ls -ltr
```

Example Output:

```text
-rw-r--r--  file1
-rw-r--r--  file1-H
```

The Hard Link has now been created.

---

# 🔬 Lab 3 – Compare Inode Numbers

One of the easiest ways to verify a Hard Link is by comparing inode numbers.

Run:

```bash
ls -li
```

Example Output:

```text
1234567 file1
1234567 file1-H
```

Notice that **both files have exactly the same inode number**.

This proves they both point to the same file data.

---

# Understanding Inodes

```text
Original File
      │
      ▼
   Inode 1234567
      ▲
      │
Hard Link
```

Both filenames reference the same inode.

# 🔬 Lab 5 – Delete the Original File

```bash

```

```bash

```

Expected Output:


The Hard Link continues to work even though the original filename has been deleted.

---

# Why Does the Hard Link Still Work?

The original filename was removed.

However:

- The inode still exists.
- The file data still exists.
- The Hard Link still references the same inode.

Linux removes the file's data only when **all Hard Links pointing to that inode have been deleted**.

---

# Hard Link Deletion Flow

```text
Original File
      │
      ▼
    Inode
      ▲
      │
Hard Link

Delete Original File

      ▼

Hard Link
      │
      ▼
    Same Inode
      │
      ▼
Data Still Exists
```

# 🔬 Lab 6 – Storage Advantage

Suppose:

Original File Size:

```text
1 GB
```

Create three Hard Links:

```bash
ln file1 file1-H1

ln file1 file1-H2

ln file1 file1-H3
```

Many students assume this consumes:

```text
4 GB
```

However, this is incorrect.

Linux stores only **one copy** of the file data.

Each Hard Link is merely another directory entry pointing to the same inode.

Therefore:

Disk usage remains approximately:

```text
1 GB
```

---

# Storage Illustration

```text
One Inode
      │
      ▼
   1 GB Data
   ┌────┬────┬────┐
   │    │    │    │
file1 H1   H2   H3
```

Multiple filenames.

One inode.

One copy of the data.


Verify:

```bash

```

Compare the inode:

```bash

```

The inode numbers should match.

---

# Why Does This Work?

Because:

```text
/
```

and

```text
/tmp
```

belong to the same file system.

Hard Links require access to the same inode table.

# 🔬 Lab 8 – Attempt to Cross File Systems

Suppose:

```text
/boot
```

is a separate file system.

Attempt to create a Hard Link:

```bash
ln file1-H /boot/file1
```

Expected Output:

```text
Invalid cross-device link
```

or a similar error message.

Linux refuses the operation because Hard Links cannot span different file systems.

---

# Why Can't Hard Links Cross File Systems?

Every file system maintains its own inode table.

An inode is only valid within the file system where it was created.

Since `/boot` has a different inode table, Linux cannot create a Hard Link pointing to an inode outside that file system.

---

# File System Illustration

```text
File System A (/)

Inode Table A
      │
      ▼
   file1

----------------------------

File System B (/boot)

Inode Table B
```

A Hard Link cannot point from one inode table to another.

---

# Hard Link Limitations

Hard Links:

- Cannot cross file systems.
- Cannot normally link directories.
- Must remain within the same mounted file system.

# 🔧 Troubleshooting

### Problem

Hard Link creation fails.

Check:

```bash
df -h
```

Verify both locations belong to the same file system.

---

### Problem

The inode numbers are different.

You probably created a Soft Link instead of a Hard Link.

Verify using:

```bash
ls -li
```

---

### Problem

The file cannot be accessed after deleting the original file.

Most likely:

- You created a Soft Link.
- Or the Hard Link was deleted as well.

# 📖 Key Takeaways

- A Hard Link is another filename pointing to the same inode.
- Both filenames share the same data.
- Both filenames share the same inode.
- Deleting the original filename does not remove the data if another Hard Link exists.
- Multiple Hard Links do not consume additional disk space for the file's contents.
- Hard Links must remain within the same file system.
- Hard Links cannot normally be created for directories.

---

# 💡 Remember

> **Think of a Hard Link as giving the same book two different titles in a library catalog.**
>
> - Both titles refer to the same physical book.
> - Removing one title from the catalog does not destroy the book.
> - The book disappears only when all catalog entries referring to it have been removed.
>
> **Golden Rule:**
>
> ```text
> Original File
>        │
>        ▼
>      Same Inode
>        ▲
>        │
> Hard Link
> ```
>
> A Hard Link is **not a copy** of the file—it is simply another name that points to the exact same inode and underlying data.
