# 📖 Introduction

Linux allows multiple file names to point to the same data.

These additional file names are called **links**.

Links provide flexibility by allowing the same file or data to be accessed from multiple locations without creating unnecessary duplicate copies.

In Windows, a similar concept is known as a **Shortcut**.

However, Linux provides two different types of links:

1. **Hard Link**
2. **Soft Link (Symbolic Link)**

Each type has its own advantages, limitations, and use cases.

---

# What is a Link?

A **link** is simply another way to access a file.

Instead of copying the file's data, Linux creates another reference to it.

This saves disk space and makes file management more efficient.

---

# Windows Shortcut vs Linux Link

| Windows | Linux |
|----------|--------|
| Shortcut | Link |
| Shortcut (.lnk) file | Hard Link / Symbolic Link |
| Points to another file | Points to the original file or its inode |

Although both provide another way to access a file, Linux links work much more closely with the file system than Windows shortcuts.

---

# Types of Links

Linux supports two types of links:

1. Hard Link
2. Symbolic Link (Soft Link)

---

# What is a Symbolic (Soft) Link?

A **Symbolic Link**, also known as a **Soft Link**, is a special file that points to another file.

It does **not** contain the actual data.

Instead, it stores the path to the original file.

Think of it like a signpost that tells Linux where the original file is located.

---

# Characteristics of a Soft Link

A Soft Link:

- Points to the original file.
- Stores the path of the original file.
- Has its own inode number.
- Has its own file permissions.
- Can cross different file systems.
- Can point to directories.
- Becomes invalid if the original file is deleted.

---

# Soft Link Illustration

```text
Original File
     │
     ▼
report.txt
     ▲
     │
Soft Link
report-link.txt
```

The Soft Link simply points to the original file.

---

# What Happens if the Original File is Deleted?

Suppose:

```text
Original File
```

is deleted.

The Soft Link still exists.

However, it now points to a file that no longer exists.

Example:

```text
Original File      ❌ Deleted

Soft Link
      │
      ▼
Broken Link
```

The Soft Link becomes a **broken link** because its target no longer exists.

---

# What is a Hard Link?

A **Hard Link** is another directory entry that points directly to the same file data stored on disk.

Instead of pointing to the file path, a Hard Link points to the same inode as the original file.

Both names are equal references to the same file.

---

# Hard Link Illustration

```text
Original File
      │
      ▼
      Inode
        │
   ┌────┴────┐
   │         │
Original   Hard Link
Filename   Filename
```

Both file names point to the same inode and the same data blocks.

---

# Characteristics of a Hard Link

A Hard Link:

- Shares the same inode as the original file.
- Shares the same file data.
- Shares the same permissions.
- Shares the same ownership.
- Cannot cross different file systems.
- Cannot link directories.
- Continues to access the data even if the original filename is deleted.

---

# What Happens if the Original File is Deleted?

Suppose:

```text
Original File
```

is removed.

The Hard Link still points to the same inode.

Therefore:

```text
Original File     ❌ Deleted

Hard Link
      │
      ▼
Same Inode
      │
      ▼
Data Still Exists
```

The file remains fully accessible through the Hard Link.

The data is only removed when **all** Hard Links to that inode are deleted.

---

# Soft Link vs Hard Link

| Feature | Soft Link | Hard Link |
|----------|-----------|-----------|
| Points to | File Path | Inode |
| Stores actual data | No | No |
| Shares inode | No | Yes |
| Can cross file systems | Yes | No |
| Can link directories | Yes | No |
| Broken if original file is deleted | Yes | No |
| Shares permissions | No | Yes |
| Shares ownership | No | Yes |

---

# Inode Numbers

One of the easiest ways to distinguish between Hard Links and Soft Links is by comparing their inode numbers.

### Soft Link

```text
Original File
Inode = 12345

Soft Link
Inode = 98765
```

Different inode numbers.

---

### Hard Link

```text
Original File
Inode = 12345

Hard Link
Inode = 12345
```

Same inode number.

---

# File Permissions

## Soft Link

A Soft Link has its own inode.

Therefore:

- It has its own file permissions.
- Changing permissions on the original file does not directly change the Soft Link's inode.

The operating system ultimately uses the target file's permissions when accessing the data.

---

## Hard Link

Because a Hard Link shares the same inode:

- Same inode
- Same owner
- Same group
- Same permissions

Changing permissions on one name immediately affects the other because both names reference the same inode.

---

# File System Limitations

Suppose you have two different file systems:

```text
/db

/oradb
```

Each mounted file system maintains its own inode table.

---

## Soft Link

A Soft Link simply stores the path to a file.

Therefore, it can point anywhere, even across different file systems.

Example:

```text
/db/report.txt
        │
        ▼
Soft Link
        │
        ▼
/oradb/report-link.txt
```

This is supported.

---

## Hard Link

A Hard Link references the same inode.

Since inode numbers are valid only within a single file system, a Hard Link cannot cross file system boundaries.

Example:

```text
/db/report.txt
        │
        ▼
Hard Link
        │
        ▼
/oradb/report-link.txt
```

This is **not allowed**.

---

# Directory Limitation

Soft Links:

✅ Can point to directories.

Hard Links:

❌ Cannot normally be created for directories.

This restriction helps prevent directory loops and protects the integrity of the file system.

---

# Real-World Example

Suppose you have:

```text
/home/student/report.txt
```

You want another convenient path:

```text
/projects/current-report.txt
```

If you create:

### Soft Link

The new file simply points to the original path.

Deleting the original file breaks the link.

---

### Hard Link

The new filename points to the same inode.

Deleting the original filename does not remove the data.

The data remains available through the Hard Link.

# Advantages of Soft Links

- Can cross file systems.
- Can point to directories.
- Flexible.
- Easy to manage.
- Useful for shortcuts.

---

# Advantages of Hard Links

- Data remains accessible if the original filename is deleted.
- No duplicate file data.
- Same inode.
- Efficient use of disk space.
- Changes made through one filename are immediately visible through the other.

---

# Disadvantages of Soft Links

- Broken if the original file is deleted.
- Different inode.
- Depends on the original file path.

---

# Disadvantages of Hard Links

- Cannot cross file systems.
- Cannot normally link directories.
- Can sometimes make file management more confusing because multiple names refer to the same data.

---

| Concept | Description |
|----------|-------------|
| Link | Another name or reference to a file |
| Hard Link | Shares the same inode as the original file |
| Soft Link | Stores the path to the original file |
| Inode | Metadata that identifies a file |
| Broken Link | A Soft Link whose target no longer exists |
| File System Boundary | Hard Links cannot cross it |

---

# 📖 Key Takeaways

- Linux supports two types of links: Hard Links and Soft Links.
- A Soft Link stores the path to another file.
- A Hard Link points directly to the same inode.
- Hard Links continue working even if the original filename is deleted.
- Soft Links become broken if the original file is removed.
- Soft Links can cross file systems.
- Hard Links cannot cross file systems.
- Soft Links can point to directories.
- Hard Links cannot normally point to directories.
- Hard Links and the original file share the same inode and file metadata.

---

# 💡 Remember

> **Think of a Soft Link as a house address and a Hard Link as another official name for the same house.**
>
> - A **Soft Link** is like writing down someone's home address. If the house is demolished or moved, the address no longer works.
> - A **Hard Link** is like giving the same house two official street names. Even if one street name is removed, the house still exists under the other name.
