# Step 1 – Check the Status of rsyslog Service

Before editing the configuration, verify that the service is running.

```bash
systemctl status rsyslog
```

Expected Output:

```text
Active: active (running)
```

If the service is not running, start it.

```bash
systemctl start rsyslog
```

Enable it during boot.

```bash
systemctl enable rsyslog
```

---

# Step 2 – Locate the rsyslog Configuration File

The main configuration file is:

```text
/etc/rsyslog.conf
```

Additional configuration files are stored inside:

```text
/etc/rsyslog.d/
```

Open the main configuration file.

```bash
vim /etc/rsyslog.conf
```

---

# Step 3 – Understand the Configuration Rules

Inside the configuration file, you will notice multiple rules.

Every rule follows the same syntax.

```text
Facility.Priority      Destination
```

Example:

```text
authpriv.*     /var/log/secure
```

Meaning:

- Facility = Authentication
- Priority = Every severity
- Destination = `/var/log/secure`

---

# Step 4 – Kernel Messages

You may find a rule similar to:

```text
#kern.*    /dev/console
```

Explanation:

- `kern` = Kernel facility
- `*` = Every priority
- `/dev/console` = Console device

This rule sends **all kernel messages** to the system console.

Notice the `#`.

It means the rule is currently **commented out** (disabled).

To activate the rule:

Simply remove the `#`.

```text
kern.*    /dev/console
```

---

# Step 5 – General System Messages

One of the most common rules is:

```text
*.info;mail.none;authpriv.none;cron.none    /var/log/messages
```

Explanation:

| Part | Meaning |
|------|----------|
| `*` | Every Facility |
| `.info` | Information level and higher |
| `mail.none` | Ignore Mail logs |
| `authpriv.none` | Ignore Authentication logs |
| `cron.none` | Ignore Cron logs |
| Destination | `/var/log/messages` |

This means:

Store all informational messages and higher from every facility except:

- Mail
- Authentication
- Cron

inside:

```text
/var/log/messages
```

---

# Step 6 – Authentication Logs

Another common rule is:

```text
authpriv.*    /var/log/secure
```

Explanation:

Authentication related logs include:

- SSH Login
- Failed Password Attempts
- sudo Commands
- su Commands
- PAM Authentication

These logs are stored inside:

```text
/var/log/secure
```

This file normally has restricted permissions because it contains sensitive security information.

---

# Step 7 – Mail Logs

Mail logs are usually configured like this:

```text
mail.*    /var/log/maillog
```

Meaning:

- Facility = Mail
- Priority = Every severity
- Destination = `/var/log/maillog`

Every mail-related event will be stored in this file.

---

# Step 8 – Emergency Messages

You may see a rule similar to:

```text
*.emerg    *
```

Explanation:

- `*` = Every facility
- `emerg` = Emergency severity
- Final `*` = Send to every logged-in user

Emergency messages are broadcast to all users currently logged into the system.

---

# Step 9 – Critical News Messages

Example:

```text
uucp,news.crit    /var/log/spooler
```

Meaning:

- Facility = UUCP and News
- Priority = Critical and higher
- Destination = `/var/log/spooler`

Only critical messages from these facilities will be recorded.

---

# Step 10 – Boot Messages

Another common rule is:

```text
local7.*    /var/log/boot.log
```

Explanation:

- Facility = local7
- Priority = Every severity
- Destination = `/var/log/boot.log`

Boot messages are written into:

```text
/var/log/boot.log
```

---

# Step 11 – Understanding Custom Application Logging

Suppose you install your own application on a Linux server.

You want all logs generated by that application to be stored inside a separate log file.

In rsyslog, you can achieve this by specifying:

- Facility
- Priority
- Destination

Example:

```text
local0.info    /var/log/myapp.log
```

Meaning:

- Facility = local0
- Priority = Information and higher
- Destination = `/var/log/myapp.log`

Now every application configured to use **local0** will write its logs into:

```text
/var/log/myapp.log
```

---

# Step 12 – Restart rsyslog After Changes

Whenever you modify the configuration file, restart the service.

```bash
systemctl restart rsyslog
```

Verify its status.

```bash
systemctl status rsyslog
```

# Step 13 – Verify Log Files

Display general messages.

```bash
tail /var/log/messages
```

View authentication logs.

```bash
tail /var/log/secure
```

View mail logs.

```bash
tail /var/log/maillog
```

View cron logs.

```bash
tail /var/log/cron
```

View boot logs.

```bash
tail /var/log/boot.log
```

# 🧠 Remember

> **Rsyslog works like a postal sorting office.**
>
> - **Facility** tells **who sent the message**.
> - **Priority** tells **how urgent the message is**.
> - **Destination** tells **where the message should be delivered (log file)**.
>
> **Formula to Remember:**
>
> ```text
> Facility.Priority      Destination
> ```
>
> Example:
>
> ```text
> authpriv.*      /var/log/secure
> ```
>
> This means:
>
> Store **all authentication messages** in `/var/log/secure`.
