# 📖 Introduction

In this lecture, we will learn how to:

```text
Log In to a Remote Linux System
```

or, in other words:

```text
Access a Linux System Remotely
```

Suppose you have a Linux server running in a data center.

One way to access that server is to physically go to the data center and use a directly connected keyboard, monitor, laptop, or management console.

That is a form of:

```text
Local / Physical Console Access
```

However, system administrators usually need to manage servers without physically standing in front of them.

For this purpose, we use:

```text
Remote Access
```

---

# Local Access vs Remote Access

## Local Access

```text
Administrator
      │
      ▼
Keyboard / Console
      │
      ▼
Linux Server
```

The administrator is directly connected to the server.

---

## Remote Access

```text
Administrator's Computer
          │
          │ Network
          ▼
      Linux Server
```

The administrator may be in:

* Another room.
* Another building.
* Another city.
* Another country.

As long as network connectivity and security policies allow it, the server can be administered remotely.

---

# Why Remote Access Is Important

Linux users and administrators frequently need shell access to remote systems.

For example, an administrator may need to:

* Check system status.
* Install software.
* Manage users.
* Restart services.
* Read logs.
* Troubleshoot applications.
* Configure networking.
* Manage web servers.
* Monitor system resources.

Traveling physically to every server would be impractical.

Remote administration solves this problem.

---

# What Is SSH?

The most common way to obtain a shell prompt on a remote Linux system is:

```text
SSH
```

SSH stands for:

```text
Secure Shell
```

SSH allows users to securely connect to another computer over a network.

---

# Basic SSH Architecture

```text
SSH Client
    │
    │ Secure Network Connection
    │
    ▼
SSH Server
    │
    ▼
Authentication
    │
    ▼
Remote Shell
```

The machine initiating the connection is the:

```text
SSH Client
```

The Linux system receiving the connection is the:

```text
SSH Server
```

---

# SSH Client-Server Example

Suppose your workstation is:

```text
Windows PC
```

and the remote machine is:

```text
RHEL 9 Server
192.168.56.102
```

The communication looks like:

```text
Windows PC
SSH Client
     │
     │ SSH
     │
     ▼
192.168.56.102
RHEL 9
SSH Server
```

After successful authentication:

```text
Windows PC
     │
     ▼
Remote Linux Shell
```

# Why Is It Called Secure Shell?

SSH provides encrypted communication between the client and server.

Conceptually:

```text
Client
   │
   │ 🔒 Encrypted SSH Connection
   ▼
Server
```

This protects information transmitted during the session.

# Command-Line SSH Method

You do not need a graphical application to use SSH.

From a Linux, macOS, or OpenSSH-enabled Windows terminal, use:

```bash
ssh username@server-ip
```

For this example:

```bash
ssh techstar@192.168.56.102
```

---

# Understanding the SSH Command

```bash
ssh techstar@192.168.56.102
```

Breakdown:

```text
ssh
 │
 └── SSH client command

techstar
 │
 └── Remote username

@
 │
 └── Separates username and host

192.168.56.102
 │
 └── Remote server IP address
```

---

# General SSH Syntax

```bash
ssh USERNAME@HOST
```

Examples:

```bash
ssh student@192.168.1.50
```

```bash
ssh admin@server1.example.com
```

```bash
ssh root@10.10.10.20
```

Whether a particular account, including `root`, is allowed to log in remotely depends on the SSH server's configuration.

# 🔧 Troubleshooting

## Problem 1 – Cannot Reach the Server

Test basic network connectivity:

```bash
ping SERVER_IP
```

Example:

```bash
ping 192.168.56.102
```

If the network is unreachable, SSH cannot connect.

---

## Problem 2 – Connection Refused

A message similar to:

```text
Connection refused
```

can indicate that the SSH service is not listening.

On the server, check:

```bash
systemctl status sshd
```

Then:

```bash
ss -lntp | grep ':22'
```

---

## Problem 3 – Connection Times Out

Possible causes include:

* Wrong IP address.
* Firewall blocking SSH.
* Network connectivity problem.
* Incorrect virtual network configuration.
* Server is powered off.

Verify the IP:

```bash
ip -br addr
```

---

## Problem 4 – Permission Denied

You may see:

```text
Permission denied
```

Possible causes include:

* Wrong username.
* Wrong password.
* Account restrictions.
* Authentication method not allowed.

Verify the username carefully.

---

## Problem 5 – `ssh` Command Not Found

Check:

```bash
command -v ssh
```

If no path appears, an SSH client may not be installed.

On many modern systems, OpenSSH client software is available by default.

---

## Problem 6 – Firewall Is Blocking SSH

On a RHEL-based server using `firewalld`, inspect:

```bash
firewall-cmd --list-services
```

You normally want:

```text
ssh
```

to be permitted.

---

## Problem 7 – Wrong Server

After logging in, always verify:

```bash
hostname
```

and:

```bash
ip -br addr
```

This is especially important when administering many systems.

---

## Problem 8 – Need to End the Session

Use:

```bash
exit
```

If the shell is responsive, this cleanly closes the remote session.

# 📖 Key Takeaways

* Remote access allows Linux administrators to manage systems without physically visiting the server.
* SSH is the standard method for obtaining secure remote shell access.
* SSH stands for **Secure Shell**.
* A remote connection requires network connectivity to the server.
* You need the server's IP address or resolvable hostname.
* You also need a valid user account and an accepted authentication method.
* MobaXterm and PuTTY can provide graphical SSH client interfaces.
* The `ssh` command provides direct command-line access.
* SSH commonly uses TCP port `22`.
* The SSH server service on RHEL systems is commonly `sshd`.
* After logging in, always verify the user and hostname.
* Commands entered during an SSH session execute on the remote server.
* The `exit` command cleanly closes the remote shell.
