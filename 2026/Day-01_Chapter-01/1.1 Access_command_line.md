# What Is a Shell?

A **shell** is an interface or medium through which users communicate with the operating system.

The shell provides an environment where users can:

* Enter commands.
* Run programs.
* Execute shell scripts.
* Manage files and directories.
* Administer the operating system.
* View command output.

In simple words:

> **The shell is an environment in which we run Linux commands, programs, and scripts.**

---

# How the Shell Works

The shell:

1. Waits for the user to enter a command.
2. Reads the command.
3. Interprets the command.
4. Requests the operating system to perform the required operation.
5. Displays the result back to the user.

---

```text
┌─────────────────────────────┐

               ▼
┌─────────────────────────────┐
│           Hardware          │
│                             │
│ CPU / RAM / Disk / Network  │
```

```text

   │

   ▼

   │
   ▼
```

# Bash and the Bourne Shell

The original Unix shell was:

```text

```

which is known as the:

```text
Bourne Shell
```

Bash was designed as an improved shell that provides many additional features.

Conceptually:

```text
Bourne Shell

     ▼
Improved / Extended Shell
     │
     ▼
```

# Checking Your Current Login Shell

After logging in to Linux, you can check your configured login shell with:

```bash
echo $SHELL
```

Example output:

```text
/bin/bash
```

This indicates that Bash is configured as your login shell.

---

# Another Way to Check Your User Account

Run:

```bash
getent passwd "$(whoami)"
```

Example output:

```text
techstar:x:1000:1000:Tech Star:/home/techstar:/bin/bash
```

The last field:

```text
/bin/bash
```

shows the user's configured login shell.

---

# Understanding `/etc/passwd`

Linux stores basic user account information in:

```text
/etc/passwd
```

Example:

```text

```

Breaking it down:

```text
techstar
   │
   └── Username

1000
   │
   └── UID

1000
   │
   └── GID

/home/techstar
   │
   └── Home Directory

/bin/bash
   │
   └── Login Shell
```

The shell displays a string when it is waiting for user input.

This is called the:

```text

```

```text
[techstar@localhost ~]$
```

A typical prompt may contain:

* Username.
* Hostname.
* Current directory.
* User privilege indicator.

# Breaking Down the Prompt

```text
[techstar@localhost ~]$
 │        │         │ │
 │        │         │ └── User privilege indicator
 │        │         │
 │        │         └── Current directory
 │        │
 │        └── Hostname
 │
 └── Username
```

---

# `$` – Regular User Prompt

If the prompt ends with:

```text
$
```

you are normally logged in as a:

```text
Regular User
```

Example:

```text
[techstar@localhost ~]$
```

The `$` character helps indicate that the current shell does not have root privileges.

---

# Regular User Example

```text
[student@server1 ~]$
```

Here:

```text
student
```

is the username.

```text
server1
```

is the hostname.

```text
~
```

represents the user's home directory.

```text
$
```

indicates a regular-user shell.

---

# `#` – Root User Prompt

If you become the root user, the shell prompt normally changes to:

```text
#
```

Example:

```text
[root@localhost ~]#
```

The `#` character indicates a:

```text
Root / Superuser Shell
```

---

# Regular User vs Root

| Prompt | User Type        |
| ------ | ---------------- |
| `$`    | Regular user     |
| `#`    | Root / superuser |

---

# Privilege Example

Regular user:

```text
[techstar@localhost ~]$
```

After becoming root:

```text
[root@localhost ~]#
```

The change from:

```text
$
```

to:

```text
#
```

is an important visual warning that you now have elevated privileges.

---

# Why the Root Prompt Matters

The root user has extensive control over the Linux system.

Root can:

* Install packages.
* Remove packages.
* Create users.
* Delete users.
* Modify system configuration.
* Start and stop services.
* Change permissions.
* Delete critical system files.

Therefore, the `#` prompt reminds administrators that they are operating with powerful privileges.

---

# ⚠️ Important Root User Warning

Commands executed as root can affect the entire system.

For example:

```text
Regular User
     │
     ▼
Limited Permissions
```

versus:

```text
Root User
     │
     ▼
Administrative Permissions
     │
     ▼
Can Affect Entire System
```

Always check your prompt before running potentially destructive commands.

# Shell vs Kernel

It is important not to confuse:

```text
Shell
```

with:

```text
Kernel
```

They perform different jobs.

---

# Shell

The shell:

* Interacts with the user.
* Accepts commands.
* Interprets commands.
* Starts programs.
* Displays output.

---

# Kernel

The kernel:

* Manages CPU.
* Manages memory.
* Manages devices.
* Manages processes.
* Manages filesystems.
* Communicates directly with hardware.

---

# Shell vs Kernel

| Shell                   | Kernel                     |
| ----------------------- | -------------------------- |
| User interface          | Core of operating system   |
| Reads commands          | Manages system resources   |
| Runs programs           | Communicates with hardware |
| Provides command prompt | Manages CPU, RAM, devices  |
| Example: Bash           | Linux kernel               |

---

```text

 │
 ▼
```

```text
HARDWARE / SYSTEM
      │
      ▼
Kernel
      │
      ▼

      │
      ▼

      │
      ▼

```

# 🔧 Troubleshooting

## Problem 1 – `echo $SHELL` Does Not Show Bash

Run:

```bash
echo $SHELL
```

Then check the user account:

```bash
getent passwd "$(whoami)"
```

Look at the final field.

Example:

```text
/bin/bash
```

---

## Problem 2 – Unsure Whether You Are Root

Run:

```bash
whoami
```

If the result is:

```text
root
```

you are root.

You can also run:

```bash
id -u
```

Root normally has:

```text
0
```

as its UID.

---

## Problem 3 – Prompt Ends with `#`

This normally means you are operating in a root shell.

Be careful before running administrative or destructive commands.

Run:

```bash
whoami
```

to verify.

---

## Problem 4 – `su -` Does Not Work

Possible reasons include:

* Incorrect root password.
* Root login restrictions.
* Root password not configured.

If your account has sudo privileges, you may instead use:

```bash
sudo -i
```

---

## Problem 5 – A Shell Command Is Not Found

Example:

```text
command not found
```

Possible reasons:

* The command is typed incorrectly.
* The required package is not installed.
* The executable is not in your `PATH`.

Check:

```bash
command -v COMMAND_NAME
```
