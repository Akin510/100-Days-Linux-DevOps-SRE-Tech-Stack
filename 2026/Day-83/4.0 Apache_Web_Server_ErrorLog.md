# Apache Main Configuration File

The main Apache configuration file is:

```text
/etc/httpd/conf/httpd.conf
```

Inside this file, Apache uses many directives that control how the web server behaves.

In this lesson, we will concentrate on:

```text
ErrorLog
LogLevel
Listen
DocumentRoot
```

---

# 1. `ErrorLog`

The `ErrorLog` directive tells Apache where server errors and diagnostic messages should be written.

A common configuration looks like:

```apache
ErrorLog "logs/error_log"
```

---

# Understanding the Error Log Path

The path:

```text
logs/error_log
```

is relative to the Apache:

```text
ServerRoot
```

If the server root is:

```apache
ServerRoot "/etc/httpd"
```

then Apache interprets:

```text
logs/error_log
```

relative to:

```text
/etc/httpd
```

Conceptually:

```text
ServerRoot
/etc/httpd
      │
      ▼
logs
      │
      ▼
error_log
```

---

# Apache Log Location on Red Hat-Based Systems

On Red Hat-based systems, `/etc/httpd/logs` commonly points to:

```text
/var/log/httpd
```

So the practical Apache error log is commonly:

```text
/var/log/httpd/error_log
```

---

# Verify the Log Link

Run:

```bash
ls -ld /etc/httpd/logs
```

Then:

```bash
ls -l /var/log/httpd/
```

You may see files such as:

```text
access_log
error_log
```

---

# View the Apache Error Log

Run:

```bash
tail /var/log/httpd/error_log
```

To watch it live:

```bash
tail -f /var/log/httpd/error_log
```

Press:

```text
Ctrl+C
```

to stop.

---

# Why Is `error_log` Important?

The error log helps troubleshoot problems such as:

* Apache failing to start.
* Configuration syntax errors.
* Permission problems.
* Missing files.
* Module problems.
* Website errors.
* Access problems.

---

# 2. `LogLevel`

Apache also allows you to control how much information is written to the error log.

This is done using:

```apache
LogLevel
```

A common example is:

```apache
LogLevel warn
```

---

# Common Apache Log Levels

You may encounter values such as:

```text
debug
info
notice
warn
error
crit
alert
emerg
```

For this lesson, the important idea is that the log level controls the amount and severity of information Apache records.

---

# Example

```apache
LogLevel warn
```

means Apache will record warning-level messages and more serious messages.

For more detailed troubleshooting, an administrator may temporarily use a more verbose level such as:

```apache
LogLevel debug
```

---

# Basic Log Level Idea

```text
More Detail
    │
    ▼
debug
info
notice
warn
error
crit
alert
emerg
    ▲
    │
More Serious
```

---

# Why Change the Log Level?

You may adjust the log level when:

* Troubleshooting.
* Investigating configuration problems.
* Debugging application behavior.
* Looking for more detailed server information.

For normal operation, the default configuration may be sufficient.

---

# 3. Apache Log Format

Apache configuration also contains directives that control how log entries are formatted.

For example, Apache may define reusable log formats and then apply them to access logs.

For beginners, it is usually fine to use the default log format.

The important point is:

> Apache lets administrators control both what is logged and how log entries are formatted.

# 4. `Listen` Directive

Another important directive is:

```apache
Listen
```

This tells Apache which network port it should listen on for incoming connections.

A common default is:

```apache
Listen 80
```

---

# What Does `Listen 80` Mean?

It means Apache is waiting for incoming HTTP connections on:

```text
TCP Port 80
```

Conceptually:

```text
Web Browser
     │
     │ HTTP
     │ TCP Port 80
     ▼
Apache Web Server
```

---

# Default HTTP Port

The default port for HTTP is:

```text
80
```

Apache commonly listens on this port for normal unencrypted web traffic.

---

# HTTP Is Not Encrypted

Traditional HTTP communication does not provide HTTPS encryption.

Conceptually:

```text
Client
   │
   │ HTTP
   │ Port 80
   │ Unencrypted
   ▼
Apache Server
```

This means sensitive information should not normally be transmitted using plain HTTP.

---

# Why Plain HTTP Is a Concern

If the traffic contains sensitive information, examples may include:

* Usernames
* Passwords
* Session information
* Personal information
* Financial information

unencrypted HTTP is not appropriate for protecting that data.

For sensitive websites, secure encrypted communication should be used.

---

# 5. HTTPS

Secure web communication normally uses:

```text
HTTPS
```

The default HTTPS port is:

```text
443
```

Conceptually:

```text
Client
   │
   │ HTTPS
   │ TCP Port 443
   │ Encrypted
   ▼
Apache Web Server
```

---

# HTTP vs HTTPS

| Feature        | HTTP                        | HTTPS           |
| -------------- | --------------------------- | --------------- |
| Default Port   | 80                          | 443             |
| Encryption     | No HTTPS encryption         | Yes             |
| Sensitive Data | Not recommended             | Preferred       |
| Typical Use    | Basic or redirected traffic | Secure websites |

---

# TLS and SSL

Secure HTTPS communication uses encryption.

Modern systems normally use:

```text
TLS
```

which stands for:

```text
Transport Layer Security
```

You may also hear the older term:

```text
SSL
```

which stands for:

```text
Secure Sockets Layer
```

In modern environments, TLS is generally used.

---

# Can the Apache Port Be Changed?

Yes.

The `Listen` directive can be changed.

For example:

```apache
Listen 8080
```

Apache would then listen on port:

```text
8080
```

instead of the default port `80`.

---

# Example

```apache
Listen 8080
```

Then the client may need to connect using:

```text
http://server-ip:8080
```

---

# Important Note

For normal HTTP websites:

```text
80
```

is the standard default.

For HTTPS:

```text
443
```

is the standard default.

Using non-standard ports is possible, but clients usually need to specify the port explicitly.

---

```text
Listen 80
```

```bash

```

# 6. Default Website Location

Apache serves website content from its:

```text
DocumentRoot
```

A common default location is:

```text
/var/www/html
```

---

# Default DocumentRoot

You may find:

```apache
DocumentRoot "/var/www/html"
```

inside:

```text
/etc/httpd/conf/httpd.conf
```

---

# Website Directory Structure

```text
/var/www/html/
      │
      ├── index.html
      ├── about.html
      ├── style.css
      ├── images/
      └── other web files
```

---

# Why `index.html` Is Important

A common default homepage filename is:

```text
index.html
```

When a browser requests the root of a website:

```text
http://server-ip/
```

Apache can serve the default page from the document root.

For example:

```text
/var/www/html/index.html
```

---

# Basic Website Flow

```text
Browser
   │
   │ GET /
   ▼
Apache
   │
   ▼
DocumentRoot
/var/www/html
   │
   ▼
index.html
   │
   ▼
HTTP Response
   │
   ▼
Browser Displays Page
```

---

# LAB 3 – Go to the DocumentRoot

Run:

```bash
cd /var/www/html
```

Verify:

```bash
pwd
```

Expected:

```text
/var/www/html
```

List the files:

```bash
ls -la
```

---

# LAB 4 – Create a Simple Website

Create:

```bash
vi /var/www/html/index.html
```

or:

```bash
nano /var/www/html/index.html
```

Add:

```html
<!DOCTYPE html>
<html>
<head>
    <title>Apache Test Page</title>
</head>
<body>
    <h1>Welcome to My Apache Web Server</h1>
    <p>This is a simple test website.</p>
</body>
</html>
```

Save and exit.

---

# Verify the File

Run:

```bash
cat /var/www/html/index.html
```

---

# Simple Website for Testing

If you want an even simpler test:

```bash
echo "Welcome to My Apache Web Server" > /var/www/html/index.html
```

This is enough to verify whether Apache can serve content.

# 7. Restart or Reload Apache

After configuration changes, Apache may need to reload or restart.

Before doing that, validate the configuration.

Run:

```bash
httpd -t
```

Expected:

```text
Syntax OK
```

---

# Restart Apache

Run:

```bash
systemctl restart httpd
```

---

# Reload Apache

If only configuration changes need to be re-read, you may use:

```bash
systemctl reload httpd
```

---

# Check Apache Status

Run:

```bash
systemctl status httpd
```

You want to see:

```text
active (running)
```

---

# Enable Apache at Boot

If required:

```bash
systemctl enable httpd
```

To enable and start it together:

```bash
systemctl enable --now httpd
```

Find the server IP address:



Open a browser and enter:

```text
http://192.168.1.100
```

If Apache is working, the page stored in:

```text
/var/www/html/index.html
```

should appear.

```text
Client Browser
```

# 9. Firewall Consideration

If remote clients cannot access the server, the firewall may need to allow HTTP.

Check:

```bash
firewall-cmd --list-services
```

If `http` is missing, add it:

```bash
firewall-cmd --permanent --add-service=http
```

Reload:

```bash
firewall-cmd --reload
```

Verify:

```bash
firewall-cmd --list-services
```

---

# HTTPS Firewall Service

For HTTPS later:

```bash
firewall-cmd --permanent --add-service=https
```

Then:

```bash
firewall-cmd --reload
```

---

# 10. SELinux Consideration

On Red Hat-based Linux systems, SELinux can also affect Apache access.

For the default directory:

```text
/var/www/html
```

the system normally already has appropriate SELinux labeling.

If you later use a custom document root, additional SELinux configuration may be necessary.

For now, using the default directory avoids unnecessary complexity.

# 🔧 Troubleshooting

## Problem 1 – Apache Does Not Start

Run:

```bash
httpd -t
```

Then:

```bash
systemctl status httpd
```

Check logs:

```bash
journalctl -u httpd
```

and:

```bash
tail /var/log/httpd/error_log
```

---

## Problem 2 – Website Does Not Display

Verify the file:

```bash
ls -l /var/www/html/index.html
```

View it:

```bash
cat /var/www/html/index.html
```

Test locally:

```bash
curl http://localhost
```

---

## Problem 3 – Local Test Works but Remote Browser Does Not

Check the firewall:

```bash
firewall-cmd --list-services
```

Add HTTP if needed:

```bash
firewall-cmd --permanent --add-service=http
firewall-cmd --reload
```

---

## Problem 4 – Apache Is Not Listening on Port 80

Check:

```bash
ss -lntp | grep ':80'
```

Then inspect:

```bash
grep -n '^Listen' /etc/httpd/conf/httpd.conf
```

---

## Problem 5 – Wrong `DocumentRoot`

Check:

```bash
grep -n '^DocumentRoot' /etc/httpd/conf/httpd.conf
```

Make sure your website is stored in the configured directory.

---

## Problem 6 – Errors Are Not Detailed Enough

Check:

```bash
grep -n 'LogLevel' /etc/httpd/conf/httpd.conf
```

For troubleshooting, a more detailed level may be temporarily useful.

Be careful with very verbose logging on production systems.

# 📖 Key Takeaways

* `ErrorLog` defines where Apache records errors.
* `LogLevel` controls the severity and amount of log information.
* Apache normally listens on TCP port `80` for HTTP.
* Plain HTTP communication is not encrypted.
* HTTPS normally uses TCP port `443`.
* HTTPS is preferred for websites handling sensitive information.
* Apache's default web directory on Red Hat-based systems is commonly `/var/www/html`.
* `index.html` is commonly used as the default webpage.
* Configuration should be validated before restarting Apache.
* `curl` is useful for testing the server without a browser.
* Access and error logs are essential for troubleshooting.
* Firewall settings may need to allow HTTP and HTTPS traffic.
