# Apache Web Server – Practice Lab: Launching a Website with Minimum Configuration

> **Hands-on Lab – Install Apache, Configure ServerName, Create `index.html`, Start `httpd`, Open the Firewall, and Test from Multiple Clients**

---

# Lab Objectives

By the end of this practice lab, students will be able to:

* Verify whether Apache is installed.
* Configure the Linux hostname for the Apache server.
* Add local hostname resolution if required.
* Install the Apache `httpd` package.
* Back up the main Apache configuration file.
* Locate and edit `ServerName`.
* Verify the default `DocumentRoot`.
* Create a simple `index.html` page.
* Start and verify the Apache service.
* Test the website locally.
* Troubleshoot remote connectivity.
* Open HTTP through `firewalld`.
* Access the website from another Linux client.
* Access the website from a Windows browser.
* Understand the minimum steps required to launch a basic Apache website.

---

# Introduction

Welcome back to the Linux classes.

This is a hands-on Apache lab.

In this exercise, we will launch a simple website with only minimal changes to the Apache configuration.

The lab environment contains:

```text
Apache Web Server
        │
        ├── Linux Client
        │
        └── Windows Client
```

The Apache server will host the website, and the client systems will access it over the network.

Assume the Apache server has:

# Step 1 – Verify Whether Apache Is Installed

On the Apache server, run:

```bash
rpm -q httpd
```

If Apache is installed, you should see a package name similar to:

```text
httpd-2.4.x-x.el9.x86_64
```

If it is not installed, you may see:

```text
package httpd is not installed
```

# Step 2 – Check the Current Hostname

Run:

```bash
hostname
```

or:

```bash
hostnamectl
```

For this lab, we want a hostname similar to:

```text
apache.techno.com
```

# Step 3 – Set the Hostname

Use:

```bash
hostnamectl set-hostname apache.techno.com
```

Verify:

```bash
hostnamectl
```

```bash
hostname
```

```text

```

```bash

```

Expected:

```text

```

On modern systems, `hostnamectl set-hostname` normally updates the persistent hostname automatically.

# Step 5 – Configure Name Resolution

If DNS is not configured for this lab, you can use `/etc/hosts`.

Edit:

```bash
vi /etc/hosts
```

Add an entry similar to:

```text
192.168.1.100 apache.techno.com www.apache.techno.com
```

Replace:

```text
192.168.1.100
```

with the actual Apache server IP address.

---

# Why `/etc/hosts` May Be Needed

When a client runs:

```text
www.apache.techno.com
```

it must translate that hostname into an IP address.

That can happen through:

```text
DNS
```

or, in a simple lab:

```text
/etc/hosts
```

```bash

```

# Step 9 – Back Up `httpd.conf`

Before editing the file, create a backup:

```bash
cp /etc/httpd/conf/httpd.conf /etc/httpd/conf/httpd.conf.bak
```

Verify:

```bash
ls -l /etc/httpd/conf/httpd.conf*
```

You should see both:

```text
httpd.conf
httpd.conf.bak
```

# Why Back Up the Configuration?

If a change causes Apache to fail, the original configuration can be restored.

```text
Original Configuration
        │
        ▼
Backup
        │
        ▼
Make Changes
        │
        ▼
Problem?
        │
        ▼
Restore Backup
```

```text

```

---

# Why Local Access Can Work While Remote Access Fails

A common situation is:

```text
Apache Server
curl localhost
     │
     ▼
Works
```

but:

```text
Remote Client
     │
     ▼
Apache Server
     │
     X
Firewall Blocks Port 80
```

The Apache application may be working correctly, but the firewall can still block remote connections.

---

# Step 23 – Allow HTTP Through the Firewall

Add the HTTP service:

```bash
firewall-cmd --permanent --add-service=http
```

Reload the firewall:

```bash
firewall-cmd --reload
```

Verify:

```bash
firewall-cmd --zone=public --list-all
```

You should now see:

```text
http
```

under allowed services.

---

# Temporary vs Permanent Firewall Rules

A runtime-only command would be:

```bash
firewall-cmd --add-service=http
```

This may disappear after firewall reload or reboot.

Permanent:

```bash
firewall-cmd --permanent --add-service=http
firewall-cmd --reload
```

For the lab, the permanent configuration is preferred.

# 🔧 Troubleshooting

## Problem 1 – `rpm -q httpd` Says Package Is Not Installed

Install:

```bash
dnf install -y httpd
```

Then verify:

```bash
rpm -q httpd
```

---

## Problem 2 – Apache Fails to Start

Check configuration syntax:

```bash
httpd -t
```

Then:

```bash
systemctl status httpd
```

Check logs:

```bash
journalctl -u httpd
```

and:

```bash
tail -50 /var/log/httpd/error_log
```

---

## Problem 3 – Website Works Locally but Not Remotely

Check firewall:

```bash
firewall-cmd --list-services
```

If `http` is missing:

```bash
firewall-cmd --permanent --add-service=http
firewall-cmd --reload
```

---

## Problem 4 – Website Name Does Not Resolve

Test:

```bash
getent hosts www.apache.techno.com
```

If nothing appears, configure:

* DNS, or
* `/etc/hosts` on Linux, or
* the Windows hosts file.

You can also test directly by IP:

```text
http://192.168.1.100
```

---

## Problem 5 – Browser Shows the Wrong Page

Check:

```bash
cat /var/www/html/index.html
```

Verify `DocumentRoot`:

```bash
grep -n '^DocumentRoot' /etc/httpd/conf/httpd.conf
```

---

## Problem 6 – Apache Is Not Listening on Port 80

Run:

```bash
ss -lntp | grep ':80'
```

Check:

```bash
grep -n '^Listen' /etc/httpd/conf/httpd.conf
```

Check service:

```bash
systemctl status httpd
```

---

## Problem 7 – `ServerName` Warning

Check:

```bash
grep -n 'ServerName' /etc/httpd/conf/httpd.conf
```

Ensure the configured hostname is valid in your lab:

```apache
ServerName www.apache.techno.com:80
```

Then validate:

```bash
httpd -t
```

---

## Problem 8 – Name Works on Server but Not Client

Remember that `/etc/hosts` is local to each Linux system.

Adding:

```text
192.168.1.100 www.apache.techno.com
```

to the server does not automatically configure the client.

The client also needs:

* DNS resolution, or
* its own hosts-file entry.

# 📖 Key Takeaways

* Apache can launch a simple website with only minimal configuration changes.
* The `httpd` package must be installed first.
* Correct hostname and name resolution are important when using website names.
* Always back up `httpd.conf` before editing it.
* `ServerName` identifies the Apache server name.
* `DocumentRoot` defines where website content is stored.
* `/var/www/html/index.html` can be used as the basic homepage.
* Apache configuration should be validated with `httpd -t`.
* The `httpd` service must be running.
* HTTP must be permitted through `firewalld` for remote access.
* Local success does not guarantee remote access.
* When local access works but remote access fails, check the firewall and name resolution first.
