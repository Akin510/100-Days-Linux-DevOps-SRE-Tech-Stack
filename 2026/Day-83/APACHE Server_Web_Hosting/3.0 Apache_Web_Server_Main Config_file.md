# 📖 Introduction

Welcome back to the Linux classes.

In this lesson, we will continue learning about **Apache Web Server**.

Our main focus is the Apache main configuration file:

```text
httpd.conf
```

This file controls many important aspects of Apache behavior.

Before configuring a web server, it is essential to understand the main configuration file and some of its most important directives.

---

# Main Apache Configuration File

The main Apache configuration file is:

```text
/etc/httpd/conf/httpd.conf
```

The directory is:

```text
/etc/httpd/conf/
```

and the main file inside it is:

```text
httpd.conf
```

---

# Apache Configuration Path

```text
/etc/httpd/
    │
    ▼
conf/
    │
    ▼
httpd.conf
```

Full path:

```bash
/etc/httpd/conf/httpd.conf
```

---

# Why `httpd.conf` Is Important

The `httpd.conf` file contains many settings that control Apache.

It is generally:

* Well commented.
* Self-explanatory.
* Large.
* Full of configuration directives.

You do not need to understand every directive immediately.

For a basic Apache setup, we will first concentrate on a few important settings.

---

# Important Rule – Always Back Up Configuration Files

Before modifying an important configuration file, always make a backup.

This is especially important for:

```text
/etc/httpd/conf/httpd.conf
```

If something goes wrong, you can restore the original file.

---

# Why Take a Backup?

Suppose you modify:

```text
httpd.conf
```

and Apache no longer starts.

Without a backup, you may have difficulty remembering the original configuration.

With a backup:

```text
Original File
      │
      ▼
Backup Copy
      │
      ▼
Edit Working File
      │
      ▼
Problem?
      │
      ▼
Restore Backup
```

---

# Backup the Apache Configuration File

A simple backup command is:

```bash
cp /etc/httpd/conf/httpd.conf /etc/httpd/conf/httpd.conf.bak
```

Verify:

```bash
ls -l /etc/httpd/conf/httpd.conf*
```

You should see:

```text
httpd.conf
httpd.conf.bak
```

---

# Recommended Backup with a Date

You may also create a dated backup:

```bash
cp /etc/httpd/conf/httpd.conf /etc/httpd/conf/httpd.conf.$(date +%F)
```

Example:

```text
httpd.conf.2026-08-15
```

# Important Apache Directives

In this lesson, we will focus on:

```text
ServerRoot
PidFile
ServerName
DocumentRoot
ErrorLog
```

These directives help define:

* Where Apache configuration files are located.
* Where Apache stores runtime process information.
* What hostname Apache uses.
* Where website files are stored.
* Where Apache writes errors.

---

# 1. `ServerRoot`

The `ServerRoot` directive defines the base directory for Apache server configuration and related files.

A common value is:

```apache
ServerRoot "/etc/httpd"
```

---

# What Does `ServerRoot` Mean?

`ServerRoot` tells Apache where its main server-related files are based.

For example:

```text
ServerRoot
    │
    ▼
/etc/httpd
    │
    ├── conf
    ├── conf.d
    ├── logs
    ├── modules
    └── run
```

---

# Example

Inside `httpd.conf`, you may find:

```apache
ServerRoot "/etc/httpd"
```

This means Apache treats:

```text
/etc/httpd
```

as its main base directory.

---

# Can `ServerRoot` Be Changed?

Yes.

It is possible to change the `ServerRoot`.

However, if you change it, the required Apache files must also exist in the new location.

For beginners and normal server administration, it is usually best to keep the default value.

---

# LAB – Find `ServerRoot`

Run:

```bash
grep -i '^ServerRoot' /etc/httpd/conf/httpd.conf
```

Possible output:

```text
ServerRoot "/etc/httpd"
```

---

# 2. Apache PID File

PID stands for:

```text
Process Identifier
```

When Apache runs, Linux assigns process IDs to Apache processes.

Apache generally has:

* One main or parent process.
* Multiple child or worker processes.

---

# Apache Process Structure

```text
Apache Parent Process
        │
        ├── Child Process 1
        ├── Child Process 2
        ├── Child Process 3
        └── Child Process 4
```

The exact number of child processes depends on the Apache process model and server workload.

---

# Why Does Apache Have Multiple Processes?

A web server may receive many requests.

Example:

```text
Client 1 ─────┐
Client 2 ─────┤
Client 3 ─────┤
Client 4 ─────┤
              ▼
         Apache Server
              │
              ├── Worker / Child
              ├── Worker / Child
              └── Worker / Child
```

Apache uses workers or child processes so that it can handle multiple requests efficiently.

---

# Apache Process Count and Traffic

As traffic increases, Apache may use additional worker processes or threads depending on its configuration.

Conceptually:

```text
Low Traffic
    │
    ▼
Few Workers

High Traffic
    │
    ▼
More Workers / Activity
```

---

# Finding Apache Processes

Run:

```bash
ps -ef | grep httpd
```

or:

```bash
pgrep -a httpd
```

You may see multiple Apache processes.

---

# Apache Runtime Information

Depending on the version and operating system, Apache runtime information may be stored under locations related to:

```text
/etc/httpd/run
```

or another runtime directory.

The PID helps administrators:

* Identify the Apache parent process.
* Monitor the server.
* Troubleshoot process problems.
* Send signals to the service if necessary.

---

# 3. `ServerName`

The `ServerName` directive defines the hostname or name that Apache uses for the server.

Example:

```apache
ServerName www.example.com
```

---

# ServerName as the Website Name

You can think of `ServerName` as the primary name associated with the Apache server.

Example:

```apache
ServerName www.apachetechno.com
```

Conceptually:

```text
User
  │
  ▼
www.apachetechno.com
  │
  ▼
Apache Web Server
```

---

# Example `ServerName`

```apache
ServerName www.example.com
```

or:

```apache
ServerName webserver.example.com
```

---

# ServerName with a Port

In some configurations, you may also see:

```apache
ServerName www.example.com:80
```

The exact configuration depends on the environment.

---

# LAB – Find `ServerName`

Run:

```bash
grep -n 'ServerName' /etc/httpd/conf/httpd.conf
```

Some installations may have the directive commented out.

Example:

```text
#ServerName www.example.com:80
```

---

# 4. `DocumentRoot`

The `DocumentRoot` directive defines where Apache stores the website files that it serves to users.

A common default location on Red Hat-based systems is:

```text
/var/www/html
```

---

# Example

Inside `httpd.conf`, you may see:

```apache
DocumentRoot "/var/www/html"
```

---

# What Is Stored in `DocumentRoot`?

Website files may include:

* HTML
* CSS
* JavaScript
* Images
* Static text
* Other web content

Example:

```text
/var/www/html/
      │
      ├── index.html
      ├── about.html
      ├── style.css
      ├── app.js
      └── images/
```

---

# Website Request Flow

```text
Web Browser
     │
     │ GET /
     ▼
Apache
     │
     ▼
DocumentRoot
     │
     ▼
/var/www/html
     │
     ▼
index.html
     │
     ▼
HTTP Response
```

---

# LAB – Find `DocumentRoot`

Run:

```bash
grep -n '^DocumentRoot' /etc/httpd/conf/httpd.conf
```

Expected result may look like:

```text
DocumentRoot "/var/www/html"
```

---

# View the Default Website Directory

Run:

```bash
ls -ld /var/www/html
```

Then:

```bash
ls -la /var/www/html
```

---

# Can `DocumentRoot` Be Changed?

Yes.

For example, you could configure:

```apache
DocumentRoot "/web/company"
```

However, if you change the location, you must also make sure that:

* The directory exists.
* Permissions are correct.
* Apache is allowed to access it.
* Related `<Directory>` configuration is correct.
* SELinux settings may need to be considered on Red Hat-based systems.

For the basic setup, we will use the default location.

---

# 5. `ErrorLog`

The `ErrorLog` directive tells Apache where to write server errors and important diagnostic messages.

A common setting is:

```apache
ErrorLog "logs/error_log"
```

---

# Relative Log Paths

Notice that this path is:

```text
logs/error_log
```

It is relative to:

```text
ServerRoot
```

If:

```apache
ServerRoot "/etc/httpd"
```

then:

```text
logs/error_log
```

is interpreted relative to the Apache server root.

---

# Apache Log Relationship

Conceptually:

```text
ServerRoot
/etc/httpd
     │
     ▼
logs
     │
     ▼
error_log
```

However, on Red Hat-based systems:

```text
/etc/httpd/logs
```

commonly points to:

```text
/var/log/httpd
```

Therefore, the practical error log location is commonly:

```text
/var/log/httpd/error_log
```

---

# Symbolic Link Example

```text
/etc/httpd/logs
       │
       │ Symbolic Link
       ▼
/var/log/httpd
```

Therefore:

```text
/etc/httpd/logs/error_log
```

corresponds to:

```text
/var/log/httpd/error_log
```

---

# Verify the Logs Link

Run:

```bash
ls -ld /etc/httpd/logs
```

Then:

```bash
ls -l /var/log/httpd/
```

---

# View Apache Error Log

Run:

```bash
tail /var/log/httpd/error_log
```

To monitor it live:

```bash
tail -f /var/log/httpd/error_log
```

Press:

```text
Ctrl+C
```

to stop following the log.

---

# Why Is the Error Log Important?

The error log helps troubleshoot problems such as:

* Apache failing to start.
* Incorrect configuration.
* Missing files.
* Permission problems.
* Invalid directives.
* Module problems.
* Website errors.

---

# Apache Directive Summary

```text
httpd.conf
    │
    ├── ServerRoot
    │      └── Base Apache directory
    │
    ├── PidFile / Runtime PID
    │      └── Apache process information
    │
    ├── ServerName
    │      └── Server / website hostname
    │
    ├── DocumentRoot
    │      └── Website files
    │
    └── ErrorLog
           └── Apache error messages
```

---

# Main Configuration File Flow

```text
Apache Starts
     │
     ▼
Reads:
/etc/httpd/conf/httpd.conf
     │
     ├── ServerRoot
     ├── ServerName
     ├── DocumentRoot
     ├── ErrorLog
     └── Other Directives
     │
     ▼
Apache Applies Configuration
     │
     ▼
Web Server Runs
```

# ⚠️ Important Best Practice

Before changing Apache configuration:

```text
1. Back up the file
2. Make one change at a time
3. Validate the configuration
4. Reload or restart carefully
5. Check the logs
```

---

# Validate Apache Configuration

Before reloading Apache, use:

```bash
apachectl configtest
```

or:

```bash
httpd -t
```

A valid configuration should report something similar to:

```text
Syntax OK
```

---

```text

   ▼

   ├── Error
   │     └── Fix Configuration
   │
   └── Syntax OK

          ▼
```

# 📖 Key Takeaways

* `httpd.conf` is the main Apache configuration file.
* It is located under `/etc/httpd/conf/`.
* Always back up configuration files before modifying them.
* `ServerRoot` identifies Apache's main server directory.
* Apache runs using parent and worker processes.
* `ServerName` defines the server hostname.
* `DocumentRoot` defines where website files are stored.
* `/var/www/html` is the common default document root.
* `ErrorLog` defines where Apache errors are written.
* Apache logs are commonly stored under `/var/log/httpd/`.
* Configuration syntax should be validated before reloading Apache.
