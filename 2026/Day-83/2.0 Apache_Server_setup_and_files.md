# Step 1 – Verify Whether Apache Is Installed

On Red Hat-based Linux systems, Apache HTTP Server is provided by the package:

```text
httpd
```

To check whether the package is installed, use:

```bash
rpm -q httpd
```

---

# Understanding `rpm -q httpd`

The command:

```bash
rpm -q httpd
```

means:

```text
rpm
 │
 └── RPM package management command

-q
 │
 └── Query the package database

httpd
 │
 └── Apache HTTP Server package
```

If Apache is installed, you should receive package information.

Example:

```text
httpd-2.4.x-x.el9.x86_64
```

The exact version depends on your system.

---

# If Apache Is Not Installed

If the package is not installed, the command may report something similar to:

```text
package httpd is not installed
```

In that case, Apache must be installed before continuing.

---

# Step 2 – Install Apache

There are different ways to install Apache depending on the environment.

Possible methods include:

* Installing from configured Linux repositories.
* Installing from an operating system installation source.
* Installing RPM packages manually.

On modern Red Hat-based systems, the usual package manager is:

```bash
dnf
```

For example:

```bash
dnf install -y httpd
```

Older Red Hat-based systems commonly used:

```bash
yum install -y httpd
```

---

# Verify the Package After Installation

After installation, run:

```bash
rpm -q httpd
```

You should now receive the installed package version.

You can also run:

```bash
dnf list installed httpd
```

---

# Apache Files and Directories

After Apache is installed, several important files and directories are available on the system.

An Apache administrator should understand these locations because they are used for:

* Starting Apache.
* Configuring Apache.
* Loading modules.
* Reading logs.
* Troubleshooting.
* Hosting website files.

---

# Important Apache Locations

Common Apache locations on Red Hat-based systems include:

```text
/usr/sbin/httpd
/etc/httpd/
/etc/httpd/conf/
/etc/httpd/conf.d/
/etc/httpd/logs/
/etc/httpd/modules/
/var/log/httpd/
```

---

# 1. Apache Server Binary

The main Apache server executable is commonly located at:

```text
/usr/sbin/httpd
```

This is the Apache HTTP Server binary.

You can verify it with:

```bash
ls -l /usr/sbin/httpd
```

You can also use:

```bash
which httpd
```

Expected output:

```text
/usr/sbin/httpd
```

---

# What Is a Binary?

A binary is an executable program.

In this case:

```text
/usr/sbin/httpd
```

is the executable program that runs the Apache Web Server.

Conceptually:

```text
Apache Package
      │
      ▼
/usr/sbin/httpd
      │
      ▼
Apache Server Process
```

---

# 2. Main Apache Configuration Directory

The primary Apache configuration directory is:

```text
/etc/httpd/
```

This directory contains important Apache configuration files and subdirectories.

List it:

```bash
ls -l /etc/httpd/
```

---

# Apache Configuration Structure

A simplified structure may look like:

```text
/etc/httpd/
   │
   ├── conf/
   │
   ├── conf.d/
   │
   ├── conf.modules.d/
   │
   ├── logs -> /var/log/httpd
   │
   ├── modules
   │
   └── run
```

The exact layout can vary depending on the distribution and Apache version.

---

# 3. Main Configuration File

One of the most important Apache files is:

```text
/etc/httpd/conf/httpd.conf
```

This is the main Apache configuration file.

View it with:

```bash
less /etc/httpd/conf/httpd.conf
```

or:

```bash
vim /etc/httpd/conf/httpd.conf
```

---

# Why Is `httpd.conf` Important?

The `httpd.conf` file controls much of Apache's behavior.

It can contain configuration related to:

* Server settings.
* Listening ports.
* Document root.
* Directory permissions.
* Logging.
* Modules.
* Access control.
* Virtual hosts.
* Other Apache directives.

---

# Apache Configuration Flow

```text
Apache Starts
     │
     ▼
Reads Configuration
     │
     ▼
/etc/httpd/conf/httpd.conf
     │
     ▼
Applies Directives
     │
     ▼
Web Server Behavior
```

---

# 4. Additional Configuration Directory

Apache also uses:

```text
/etc/httpd/conf.d/
```

This directory contains additional configuration files.

List them:

```bash
ls -l /etc/httpd/conf.d/
```

These files may contain settings for additional Apache features.

---

# Why Use `conf.d`?

Instead of placing every setting inside one large `httpd.conf` file, Apache can load additional configuration files.

This helps keep configuration organized.

Examples may include:

* SSL configuration.
* Application-specific settings.
* PHP-related settings.
* Additional web server features.

---

# Example Configuration Structure

```text
/etc/httpd/conf/httpd.conf
          │
          ▼
Main Apache Configuration
          │
          ├── General Settings
          │
          └── Includes Additional Files
                    │
                    ▼
             /etc/httpd/conf.d/
                    │
                    ├── ssl.conf
                    ├── custom.conf
                    └── other.conf
```

---

# 5. Apache Module Configuration

Apache supports many modules.

Modules extend Apache's functionality.

Configuration related to modules may be stored in locations such as:

```text
/etc/httpd/conf.modules.d/
```

Apache's module files may also be available under:

```text
/etc/httpd/modules/
```

or through a symbolic link to the actual module directory.

---

# What Is an Apache Module?

A module adds extra capabilities to Apache.

Examples of Apache functionality can include:

* SSL/TLS support.
* Authentication.
* URL rewriting.
* Proxy functionality.
* Compression.
* Logging.
* Other web server features.

---

# Module Concept

```text
Apache Core
    │
    ├── Module A
    ├── Module B
    ├── Module C
    └── Module D
```

Instead of putting every possible feature directly inside the Apache core, modules provide additional functionality when needed.

---

# 6. Apache Log Files

Logs are extremely important when administering Apache.

Apache logs help you understand:

* Who accessed the server.
* What pages were requested.
* What errors occurred.
* Whether Apache started successfully.
* Whether configuration problems exist.

---

# Apache Log Location

A common log location is:

```text
/var/log/httpd/
```

List the directory:

```bash
ls -l /var/log/httpd/
```

You may see files such as:

```text
access_log
error_log
```

---

# Access Log

The access log records client requests.

Example:

```text
/var/log/httpd/access_log
```

View recent entries:

```bash
tail /var/log/httpd/access_log
```

Follow it live:

```bash
tail -f /var/log/httpd/access_log
```

---

# Error Log

The error log records Apache errors and important server messages.

Example:

```text
/var/log/httpd/error_log
```

View recent entries:

```bash
tail /var/log/httpd/error_log
```

Follow it live:

```bash
tail -f /var/log/httpd/error_log
```

---

# Apache Logs Symbolic Link

You may also see:

```text
/etc/httpd/logs
```

This may be a symbolic link pointing to:

```text
/var/log/httpd
```

Verify:

```bash
ls -ld /etc/httpd/logs
```

Example:

```text
/etc/httpd/logs -> ../../var/log/httpd
```

---

# What Is a Symbolic Link?

A symbolic link is a reference that points to another file or directory.

Conceptually:

```text
/etc/httpd/logs
       │
       │ Symbolic Link
       ▼
/var/log/httpd
```

This means both paths can lead you to the Apache log location.

---
# Linux Hands-On: Creating a Symbolic Link (Symlink)

This quick lab demonstrates how to create a **symbolic link** (soft link) from a convenient path (`/opt/logs`) pointing directly to an actual application log directory (`/var/log/app_logs`).

---

## Step 1: Create the Target Directory & Sample Log

First, create the destination directory and populate it with a dummy log file:

```bash
mkdir -p /var/log/app_logs
echo "Application started successfully." > /var/log/app_logs/app.log
```

---

## Step 2: Create the Symbolic Link

Use the `ln -s` command following the syntax `ln -s <TARGET_DIRECTORY> <LINK_NAME>`:

```bash
ln -s /var/log/app_logs /opt/logs
```

---

## Step 3: Verify the Link

Verify that the symlink was created correctly using `ls -l`:

```bash
ls -l /opt/logs
```

**Expected Output:**
```text
lrwxrwxrwx 1 root root 17 Aug 16 10:22 /opt/logs -> /var/log/app_logs
```

* **Note:** The `l` attribute at the very beginning of the permissions string indicates that this file is a **symbolic link**.

---

## Step 4: Test Access via the Symlink

Read the log file using the shortcut path to confirm it accesses the original location:

```bash
cat /opt/logs/app.log
```

**Expected Output:**
```text
Application started successfully.
```

---

## Key Takeaways for Students

* **Shortcut Behavior:** A symbolic link acts like a shortcut pointer in GUI operating systems.
* **Data Safety:** Removing the shortcut (`rm /opt/logs`) deletes **only** the link pointer—the actual log files inside `/var/log/app_logs` remain completely intact.

# 7. Runtime Information

Apache also needs runtime information while the service is running.

This can include:

* Process information.
* PID files.
* Runtime state.

Some Apache installations provide runtime-related locations under:

```text
/etc/httpd/run
```

or a linked runtime directory.

---

# What Is a PID?

PID means:

```text
Process Identifier
```

When Apache runs, Linux assigns its processes unique process IDs.

You can inspect Apache processes with:

```bash
ps -ef | grep httpd
```

or:

```bash
pgrep -a httpd
```
